## Relatório de conclusão (verbatim)

**B04c concluído** — ADR 008 implementado de ponta a ponta, com o ciclo completo validado no PDF real: conversão → documento.md → revisão humana → reprocessamento barato. 165 testes, `make check` e `make map` verdes. Parado para sua revisão.

**O que foi implementado:**

1. **Parser único** (`ingest/markdown.py`) — convenção (`# título`, `*subtítulo*` após o título, `<!-- p.N -->`, parágrafos por linha em branco), escape/unescape mínimo (texto de documento nunca é interpretado como marcação), `parse_markdown` → IngestResult. Contrato ganhou `ParagraphKind.subtitulo` e `Paragraph.page`; `locate` devolve "cap. X, subtítulo".
2. **Conversores** — `convert_docling.py` (segue a ordem de leitura do body; section_header após título explícito vira subtítulo; page_header/footer viram RemovedItem), `canonical.py` (rota pdf_loader, agora produz MdBlocks), `convert_txt.py` e `convert_pandoc.py` (experimental, pandoc na imagem dev). Todos passam pela mesma precedência genérica de títulos.
3. **Layout e cache** (`ingest/store.py`) — `data/processed/<hash_do_arquivo>/` com `source.json`, `docling/2.150.0-noocr-notables-imgplaceholder-b1/docling.json` (cache 1× por documento), `documento.md`, `conversao.json` (preserva removidos/alertas da conversão para reparses), derivados e comparação. Docling pinado em 2.150.0; chave de cache no código e flags no Makefile com nota de sincronia.
4. **CLI** — `ingest` multi-formato (PDF/TXT/EPUB/DOCX/HTML; exit 3 = cache ausente), `prepare`, `compare`, `clean` (lista órfãs; `--apply` remove). `make ingest` roda o Docling automaticamente no cache miss; `make docling` é idempotente; `make clean-processed` (`APPLY=1`).
5. **documento.md é a fonte**: nunca sobrescrito sem `--force-md`; editar muda o hash canônico (coberto por teste).

**Medição (fatia de 40 páginas, VM 3,7 GiB):** padrão 84,4 s / pico 3,05 GiB; com `--no-ocr --no-tables --image-export-mode placeholder --page-batch-size 1` **64,2 s / 2,32 GiB** (−24% tempo, −22% memória). O pico de ~3 GiB do modo padrão explica o OOM do livro inteiro; os 8 GiB na VM continuam pendentes para as 379 páginas.

**Validação do ciclo no PDF real (fatia):**
- `make ingest` (cache miss): Docling rodou 1×, documento.md gerado, 138 parágrafos, 4 "capítulos" errados do layout + alertas corretos ("capítulos vindos só do layout", "capítulo N sem parágrafos").
- **Achado novo**: o Docling fundiu "C A P Í T U L O I" com o subtítulo num só item de texto — por isso nenhum título explícito foi reconhecido nesta fatia.
- Edição humana simulada no documento.md (separar título/subtítulo, demover paratexto) + `make ingest` de novo: **sem Docling**, ~segundos, resultado correto — 1 capítulo, `locate` devolve "cap. 1, subtítulo" e "cap. 1, § 1", subtítulo com página 4 via marcador.
- `make clean-processed`: listou as 2 pastas do layout antigo como órfãs, sem apagar (remoção é decisão sua com `APPLY=1`).

**Pontos para sua revisão:**
1. O alerta "capítulos vindos só do layout do Docling" persiste após a edição humana porque vem do `conversao.json` (registro da conversão). Documentado; se preferir, posso suprimi-lo quando o .md foi editado.
2. O caso "título fundido com subtítulo pelo Docling" ficou para a revisão humana (como a arquitetura prevê). Dá para tentar um split genérico (prefixo de letras espaçadas + romano), mas preferi não criar heurística nova sem ver os seus 3–5 PDFs variados.
3. As pastas antigas (`13cfb1…`, `317f9a…`) e `data/docling/` do layout anterior podem ser removidas com `make clean-processed APPLY=1` + `rm -r data/docling` quando você quiser.
